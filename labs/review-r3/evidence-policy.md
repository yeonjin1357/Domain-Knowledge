# 3라운드 증거 묶음 정책

확인일: 2026-10-05. 이번 단계는 실행 준비이며 Linux 실행 결과를 주장하지 않는다.

- 출판 단위는 요약 JSON **및 그 JSON이 가리키는 모든 gzip 파일**이다. `.lab-runs/r3/이름.json`과 `이름.raw/`를 함께 보존하고, 3d에서 함께 `labs/results/`로 복사한다. 원본을 버리고 hash만 출판하지 않는다.
- JSON에는 입력 파일 SHA256, 고정 자산, 적용 환경, 성공·반증 조건, 판정, 단위가 있는 관측값, 원시 자료 이름을 넣는다. gzip에는 실제 명령 출력·조회 원문을 보존한다. 압축 전후 바이트 수와 SHA256을 모두 검사한다. gzip 헤더의 mtime은 0이다.
- 한 JSON은 1 MiB, 원시 자료 하나는 압축 전 16 MiB, 전체 원시 자료는 압축 전 64 MiB 이하로 제한한다. 한도를 넘기면 실패로 기록하며 자른 자료로 성공을 주장하지 않는다. 명령에는 시간 제한을 둔다. 오류 시 남긴 workspace는 진단용이며 출판 증거와 구분한다.
- 결과 이름과 sidecar 디렉터리는 독점 생성한다. 같은 이름의 재실행은 거부한다. 재실행에는 새 이름을 쓴다. 검증기는 경로 이탈, 파일 누락, gzip 손상, hash·크기 불일치를 거부한다.
- 동일 원문을 여러 번 복사하지 않는다. 예를 들어 프로세스 메모리 비용 측정은 반복별 시간·읽은 바이트 수를 기록하고, 원문은 단계별로 한 번 저장한다. 작은 SQL 결과는 요약에도 표시하지만 원래 XML과 SQL을 함께 남긴다.
- 실패·차단·반증을 성공으로 바꾸지 않는다. `recorded`는 기록/정리 완료를 뜻하고 가설 지지는 각 시나리오의 `verdict`로 판단한다. 실행 전 준비 검사는 실제 Linux 동작 검증이 아니다.
- Linux 네이티브 임시 디렉터리는 권한이 필요한 데이터·소켓용으로만 쓴다. 소유 프로세스를 먼저 종료한 뒤 자신이 만든 디렉터리만 제거한다. 정리 실패는 오류로 남긴다. 시스템 설치·서비스 등록·시간 설정·기존 DB 접속은 금지한다.

기존 2라운드 결과는 변경하지 않는다. 향후 보관 형식을 바꾸려면 기존 원문 hash를 연결한 별도 압축 증거를 추가하고 독립 검증을 거친다. Git 이력 재작성이나 기존 출판 근거 교체는 이번 작업에 포함하지 않는다.
